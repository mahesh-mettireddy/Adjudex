# Adjudex Demo Runbook

Adjudex is ready for a short hackathon presentation. The recommended demo
takes about three minutes and shows the product promise without requiring the
audience to understand the entire API.

## Before presenting

Run:

```bash
npm install
npm run dev:all
```

Open `http://localhost:5173`.

If Gemini is available:

1. Copy `.env.example` to `.env`.
2. Set `GEMINI_API_KEY`.
3. Restart `npm run dev:all`.
4. Confirm the API log says `Gemini: enabled`.

If Gemini is unavailable, continue anyway. The local deterministic generator
keeps the demo functional and labels the fallback.

## Presentation story

### 1. Frame the problem

Use this opening:

> AI agents can now spend a user's money. When a transaction goes wrong, how
> do we prove whether the agent followed the user's instructions?

Then show the mandate:

```text
Maximum: ₹8,000 per night
Allowed merchants: OYO, Taj Bookings, MakeMyTrip
Refundable booking required
Quiet room requested
```

### 2. Run the clean case

Click **Run clean case**.

Expected result:

```text
IN MANDATE
Liability: None
```

Point out that price, merchant, refundability, dates, and evidence all pass.

### 3. Run the breach case

Click **Try a breach**.

Expected result:

```text
OUT OF MANDATE
Liability: Agent Provider
```

Explain that the merchant and price violate the signed mandate. This is a
reproducible rule result, not an AI opinion.

### 4. Show safe abstention

Use the ambiguous sample from the Cases panel.

Expected result:

```text
ABSTAIN
Human review required
```

Explain:

> The hard constraints pass, but “quiet room” was never defined with
> machine-checkable evidence. Adjudex refuses to guess.

This is the strongest trust and safety moment in the demo.

### 5. Generate a random case

Click **Generate random case**.

Explain the separation:

```text
Gemini generates the execution
        ↓
Adjudex validates the JSON
        ↓
Deterministic engine computes the verdict
```

Show the generation metadata if available:

```text
Generated by Gemini
or
Generated locally — Gemini unavailable
```

The local fallback is intentional. The core demo must not depend on an
external model or network connection.

### 6. Show the audit

Open the audit details or use the copy/download action. Highlight:

- Verdict.
- Liability code.
- Constraint results.
- Verdict ID.
- Input hash.
- Engine version.
- Ruleset version.
- Evaluation timestamp.

Close with:

> Every decision can be replayed, explained, and audited.

## What to emphasize to judges

- The deterministic engine is authoritative.
- Gemini is assistive, not the liability decision-maker.
- The system supports three honest outcomes: pass, breach, and abstain.
- Every constraint is visible and explainable.
- Invalid AI output is rejected and replaced by a clearly labelled local
  fallback.
- The same engine works in the browser, through the API, and as a library.

## What not to claim

The current project is not yet a complete production platform. Do not claim:

- Durable production persistence.
- Complete user authentication.
- Legal liability determination.
- Real merchant integrations.
- Zero-risk AI operation.

Describe it as:

> A deterministic control and audit layer for AI agents that spend money.

## Recovery checklist

If Gemini fails during the presentation:

1. Continue with the built-in clean, breach, and ambiguous cases.
2. Use the local generator; its response will identify the fallback.
3. Show the audit record and explain that the verdict engine is independent of
   Gemini.
4. Do not retry repeatedly or hide the fallback.

If the API is unavailable:

1. Run `npm run dev` for browser-local mode.
2. Use the built-in scenarios.
3. Explain that the same deterministic engine is also exposed through the API.
